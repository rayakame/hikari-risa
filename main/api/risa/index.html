risa¶

A component handler for hikari, built on Discord's Components V2.

A view is a class whose fields are its state, whose render returns its layout, and whose handlers answer the clicks on it. The state travels inside the message by default, so views survive restarts with no infrastructure, or lives in a store for views that outgrow it.

bind module-attribute ¶

bind = functools.partial

Put a handler on a component together with its wire arguments.

ui.Button(risa.bind(self.vote, 2)) routes a click on that button to vote(ctx, 2). It is functools.partial, so arguments go by position or by name, and nested bind calls merge as partials do: a keyword given twice takes the outer value.

AutoDefer ¶

Bases: StrEnum

How risa answers a click whose handler has not answered in time.

Discord fails an interaction that gets no answer within three seconds. With auto-defer, risa acknowledges the click in the handler's place after the client's auto_defer_delay, and the handler carries on. Set it on the client, on a view with @risa.register(defer=...), or on a handler with @risa.handler(defer=...); the most specific setting wins.

Attributes:

  • OFF –

    Never answer in the handler's place. The default.

  • UPDATE –

    Acknowledge silently, for a handler that answers with ctx.rerender() or ctx.edit(...).

  • THINKING –

    Show a "thinking..." message, for a handler that answers with ctx.respond(...), which then takes its place.

  • THINKING_EPHEMERAL –

    The same, visible only to the user who clicked.

Client ¶

Bases: ABC

Routes clicks on registered views to their handlers.

Make one with client_from_app or client_from_lightbulb, add views with add_view, and send a view with build. A client answers only custom_ids risa wrote, so it can share a bot with other component handlers.

Parameters:

  • use_global (bool, default: False ) –

    Also route views registered with @risa.register but never added to this client.

  • di (DependencyInjectionManager | None, default: None ) –

    The linkd manager handlers are injected from; a new one by default.

  • register_app_dependencies (bool, default: True ) –

    Register the app, its REST client, and its event manager or interaction server for injection.

  • auto_defer (AutoDefer, default: OFF ) –

    The AutoDefer of views and handlers that set none, OFF by default.

  • auto_defer_delay (float, default: AUTO_DEFER_DELAY ) –

    Seconds after which auto-defer answers a click in its handler's place.

  • store (Store | None, default: None ) –

    The store InStore views use unless they name another.

  • stores (Mapping[str, Store] | None, default: None ) –

    Further stores, by the name InStore(store=...) refers to them by.

  • key_prefix (str | None, default: None ) –

    The prefix of every store key, risa:{application id} by default. Set it to fit a Redis ACL pattern, or to separate bots that share one store.

Raises:

  • ValueError –

    If key_prefix is blank, or the default store is given both as store and in stores.

build async ¶

build(view)

Render view into the components of a new message, ready to send.

await ctx.respond(**await client.build(Poll(question="Ship it?")))

It runs the view's load, renders it, and writes an InStore view's first record. The result spreads into any hikari or lightbulb call that takes components=. If that send fails, the record stays behind until its TTL reaps it, or for good under InStore(ttl=None).

Returns:

  • Rendered –

    The components, as a mapping that spreads into a send.

Raises:

  • NotAViewError –

    If the view's class was never registered.

  • ViewDeclarationError –

    If the view keeps its state in a store this client does not have.

  • StateOverflowError –

    If an InMessage view's state does not fit its components.

ComponentContext ¶

Bases: Context[ComponentInteraction]

The context of a click on one of a view's components.

A handler answers through it: rerender() redraws the message from the view's state, edit(...) replaces it with another layout, and respond(...) sends a new message.

message property ¶

message

The message the component is on, if any.

values property ¶

values

The values picked in a select menu; empty for a button.

resolved property ¶

resolved

The users, members, roles and channels picked in an entity select menu, or None.

edit async ¶

edit(layout)

Replace the message with layout, keeping the view's state on it.

For a screen the view's render does not draw, such as a confirmation or a closing message. A layout without interactive components ends the view, since nothing on it can be clicked any more. Like rerender(), it saves the view's state.

Raises:

  • NoViewError –

    If the layout has interactive components but this context has no view state, as in on_outdated and on_state_missing.

  • EphemeralOriginError –

    If the message is ephemeral and the interaction was answered with a new message.

  • StateOverflowError –

    If an InMessage view's state does not fit the layout's components.

  • StateConflictError –

    If another process saved the view's state first. The view then holds that state.

rerender async ¶

rerender()

Redraw the message from the view's current state, and save that state.

Every rerender is a commit. InMessage state is written into the message itself; InStore state goes to the store first, then the message is edited. A change made without calling it is saved when the handler returns, but that save can only log a failure; call it yourself, before any respond(), where a failure must be handled.

Raises:

  • NoViewError –

    If the view has durable fields but this context has no view state, as in on_outdated and on_state_missing.

  • EphemeralOriginError –

    If the message is ephemeral and the interaction was answered with a new message.

  • StateOverflowError –

    If an InMessage view's state no longer fits its components.

  • StateConflictError –

    If another process saved the view's state first. The view then holds that state, and the handler can apply its change again and rerender.

  • StateNotFoundError –

    If an InStore view's record disappeared while the handler ran.

acknowledge async ¶

View ¶

Bases: Struct

Base class of a view: a message's layout, its state, and the handlers behind it.

A view is a msgspec.Struct, and its annotated fields are its durable state, carried from click to click. Mark a field risa.Prop[...] to rebuild it fresh on every click instead, typically in load. Register the class with @risa.register, return its layout from render, and send it with client.build:

@risa.register(name="counter")
class Counter(risa.View):
    count: int = 0

    def render(self) -> ui.Layout:
        return ui.Row(ui.Button(self.add, label=f"Clicked {self.count} times"))

    @risa.handler
    async def add(self, ctx: risa.ComponentContext) -> None:
        self.count += 1
        await ctx.rerender()

Each click runs its handler on the latest saved state of its view, and clicks on one view queue up within a process, each waiting up to ten seconds for the lock; one that waits longer is logged and goes unanswered. A view without durable fields has nothing to protect and takes no lock, so its handlers may run at the same time. Across processes, an InStore view on a shared store lets the first write win, while for an InMessage view the last edit of the message wins. A change made without ctx.rerender() is saved when the handler returns, but that save can only log a failure, so a handler that must know calls ctx.rerender() itself, before any ctx.respond(). A handler that raises keeps what it saved through rerender() or edit() before, and loses the rest.

render ¶

render()

Return the view's layout, drawn from its current state.

It runs for the first send and for every rerender. Keep it synchronous and free of I/O; fetch what it shows in load.

load async ¶

load()

Fill the view's props before it renders.

risa awaits it before the first send and on every click, after restoring the durable state and before the handler runs. Its parameters are injected, as a handler's are.

on_outdated async classmethod ¶

on_outdated(ctx)

Answer a click on a component this view can no longer route.

The component's handler was retired by a version bump, its wire parameters changed without one, or its state was written by durable fields the view no longer has. The default does nothing, so the click fails on the user's side, and risa logs it. Override it to answer the user, or to replace the dead message with ctx.edit(...). Its parameters are injected, as a handler's are, and ctx has no view state.

To answer clicks on one retired handler differently, keep a method with its id, version and wire parameters whose body says the component is outdated. It routes like any handler, and nothing is logged.

on_state_missing async classmethod ¶

on_state_missing(ctx)

Answer a click on an InStore view whose state is gone.

The record expired or was deleted. The default does nothing, so the click fails on the user's side, and risa logs a warning. Override it to answer the user, or to replace the message with ctx.edit(...). Its parameters are injected, as a handler's are, and ctx has no view state.

handler ¶

handler(func: HandlerFunction[V, P]) -> HandlerMethod[V, P]

handler(*, handler_id: str | None = ..., version: int = ..., defer: AutoDefer | None = ...) -> _HandlerDecorator

handler(func=None, /, *, handler_id=None, version=1, defer=None)

Make a view method a handler that components can route to.

Use it bare or with options. A handler takes the view and a ComponentContext, then its wire parameters, then anything to inject:

@risa.handler(defer=risa.AutoDefer.UPDATE)
async def vote(
    self, ctx: risa.ComponentContext, option: int, db: Database
) -> None: ...

Wire parameters come first, are positional, and are annotated bool, int, str, hikari.Snowflake or an enum.Enum of int or str values. They receive the values risa.bind put on the component. Every parameter after them is injected through linkd, so a hikari enum such as hikari.ChannelType, which is not an enum.Enum, is injected too; to carry one on the wire, bind its value as an int. A handler returns None.

Parameters:

  • handler_id (str | None, default: None ) –

    The id the handler routes under, the method's name by default. Pin it before renaming the method, so components already sent keep working.

  • version (int, default: 1 ) –

    Bump it when the wire parameters change. Components sent before keep routing to a method that still has the old version; once none does, they go to View.on_outdated.

  • defer (AutoDefer | None, default: None ) –

    The handler's AutoDefer, overriding the view's.

Returns:

  • HandlerMethod | Callable[[HandlerFunction], HandlerMethod] –

    The handler, or a decorator that makes one when options are given.

register ¶

register(*, name, version=1, defer=None, state=DEFAULT_PLACEMENT)

Register a view class so its components can be routed.

@risa.register(name="poll", state=risa.InStore(ttl=30 * 86400))
class Poll(risa.View): ...

A client then routes it once it is passed to client.add_view. The decorator raises ViewDeclarationError for a class risa cannot serve, such as a blank name, a prop without a default, or an InStore view without durable fields.

Parameters:

  • name (str) –

    The name the view routes under. Renaming it retires every component already sent.

  • version (int, default: 1 ) –

    The schema version of the durable state. Appending fields that have defaults needs no bump; any other change to the durable fields does, and components sent before the bump no longer route to the view.

  • defer (AutoDefer | None, default: None ) –

    The view's AutoDefer, for handlers that set none.

  • state (StatePlacement, default: DEFAULT_PLACEMENT ) –

    Where the durable state lives: InMessage(), the default, or InStore(...).

Returns:

  • Callable[[type[T]], type[T]] –

    The decorator. It returns the class unchanged.
