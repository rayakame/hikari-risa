risa.store¶

Stores for InStore state: the Store protocol and the stores risa ships.

MemoryStore is importable from here. risa.store.redis.RedisStore and risa.store.postgres.PostgresStore live in their own modules, which need the [redis] and [postgres] extras.

DEFAULT_MAX_ENTRIES module-attribute ¶

DEFAULT_MAX_ENTRIES = 10000

How many entries a MemoryStore keeps before it evicts the least recently used.

DEFAULT_LOCK_TIMEOUT module-attribute ¶

DEFAULT_LOCK_TIMEOUT = 10.0

Seconds Store.lock() waits for a key before it raises LockTimeoutError.

MemoryStore ¶

Bases: Store

A store that keeps state in this process's memory.

Meant for development and tests: the state is lost on every restart, and other processes cannot see it, so the client warns when an InStore view uses one. Past max_entries, each new entry pushes out the least recently used one.

Parameters:

  • max_entries (int, default: DEFAULT_MAX_ENTRIES ) –

    How many entries to keep.

  • clock (Callable[[], float], default: monotonic ) –

    The monotonic clock, in seconds, that expiry is measured on.

get async ¶

get(key)

Return the data under key, or None if there is none or it has expired.

get_versioned async ¶

get_versioned(key)

Return the data and version under key, or None if there is none or it has expired.

put async ¶

put(key, value, *, ttl)

Write value under key, whether or not an entry exists.

The entry's version changes. ttl is the entry's lifetime in seconds from now, and None clears any expiry, so the entry lives until it is deleted.

put_if_version async ¶

put_if_version(key, value, *, expected, ttl)

Write value under key only if the entry is still at version expected.

The compare and the write are one atomic step: of several writers expecting the same version, exactly one succeeds. ttl works as in put.

Returns:

  • int | None –

    The entry's new version, or None if the entry is missing, expired, or at a different version, in which case nothing was written.

delete async ¶

delete(key)

Remove the entry under key, if there is one.

touch async ¶

touch(key, *, ttl)

Restart the lifetime of the entry under key, which now expires ttl seconds from now.

The data and version stay as they are, and a missing key stays missing.

lock ¶

lock(key, *, timeout=DEFAULT_LOCK_TIMEOUT)

Hold key exclusively while the returned context manager is entered.

risa holds it for the length of a click, so clicks on one view run one after another. A store that several processes share should exclude all of them; when such a lock lapses, the version check of put_if_version still decides whose write lands.

Raises:

  • LockTimeoutError –

    If the lock is not granted within timeout seconds.

VersionedEntry ¶

Bases: Struct

An entry as a store holds it.

Attributes:

  • data (bytes) –

    The bytes last written.

  • version (int) –

    The version of that write. It changes with every write to the entry.

Store ¶

Bases: Protocol

Where risa keeps the state of InStore views.

Implement it to keep state somewhere risa ships no store for, and check the implementation with risa.store.testing.verify_store. A missing or expired entry is never an error: it reads as None. Apart from LockTimeoutError from lock, any exception a method raises means the backend could not be reached, and risa reports it as StoreUnavailableError.
