Hooks¶

A hook is a function risa runs before or after the handler of a click: a check that turns the click away, a limit, an audit once it is done. Attach it to the client, a view or a handler.

risa ships the common ones as ready-made hooks.

The model is lightbulb's: the steps and most names are the same, so what you know from its hooks carries over.

A check¶

Anyone can click Close on this poll, and only its author should. A check is a hook in the CHECKS step that raises when the click may not go on:

class NotTheAuthorError(Exception):
    """Someone other than the author tried to close the poll."""


@risa.hook(risa.ExecutionSteps.CHECKS)
async def author_only(_pipeline: risa.ExecutionPipeline, ctx: risa.ComponentContext, poll: Poll) -> None:
    if ctx.user.id != poll.author_id:
        raise NotTheAuthorError

@risa.hook makes author_only a hook. It takes the click's ExecutionPipeline and the context. Its third parameter is annotated Poll, so it also gets the poll with its durable state.

@risa.handler(hooks=[...]) attaches it to close alone:

@risa.handler(hooks=[author_only])
async def close(self, ctx: risa.ComponentContext) -> None:
    self.closed = True
    await ctx.rerender()

Answering a check¶

Without an error handler the click fails in Discord, and risa logs it. This one answers instead:

@client.error_handler
async def not_the_author(pipeline: risa.ExecutionPipeline, ctx: risa.ComponentContext) -> bool:
    if pipeline.find(NotTheAuthorError) is None:
        return False
    await ctx.respond("Only the author can close this poll.", ephemeral=True)
    return True

A hook can also answer the click itself through ctx, as a handler would. A handler that answers after it then sends a follow-up.

The steps¶

By default a click runs through six steps, in this order:

  1. 1MAX_CONCURRENCYHow many run at once.
  2. 2CHECKSWhether it may run.
  3. 3COOLDOWNSHow often it may run.
  4. 4PRE_INVOKERight before the handler.
  5. 5INVOKEload(), the handler, the save.
  6. 6POST_INVOKEAfter the handler, even after a failure.

A step's name only says what it is meant for: risa runs every step's hooks the same way.

  • INVOKE takes no hooks. @risa.hook raises HookDeclarationError for it.
  • Hooks see the state, locked. On a view with durable fields, hooks run after risa has read the state and taken its lock, so a check sees the fields as they are, and no other click on the message gets in between.
  • Props are still at their defaults, because load() runs in INVOKE.
  • Hooks take time. They count toward auto-defer's delay and Discord's three seconds, as the handler does.

Where a hook goes¶

Attach it with It runs for
risa.client_from_app(..., hooks=[...]) Every click on every view of the client
@risa.register(..., hooks=[...]) Every click on the view
@risa.handler(hooks=[...]) The clicks on that handler

client_from_lightbulb takes hooks= too.

Within a step, the client's hooks run first, then the view's, then the handler's, each in the order of its list. A hook you attach in two places runs twice.

When a hook fails¶

A hook fails the click by raising. Then:

  • The hooks after it still run, so every check has its say. A hook made with skip_when_failed=True is skipped once anything in the click has failed, the handler included.
  • If INVOKE has not run yet, it does not run: not load(), not the handler, not a fallback.
  • POST_INVOKE runs, so a hook after the handler can release what one before it took.
  • The view is gone from ctx, as in an error handler. On a view with durable fields, ctx.rerender() and ctx.edit() with something to click raise NoViewError, so a half-changed view is never saved. A hook that takes the view still gets it to read.
  • The error handlers run once, when the click is over. pipeline.failures lists every Failure in order, each with its exception, its stage and its hook.

After the handler¶

The client runs audit after every click on every view:

@risa.hook(risa.ExecutionSteps.POST_INVOKE)
async def audit(pipeline: risa.ExecutionPipeline, ctx: risa.ComponentContext) -> None:
    outcome = "failed" if pipeline.failed else "ran"
    AUDIT.info("%s clicked on message %s, which %s", ctx.user.id, ctx.message.id, outcome)

hooks= on the client attaches it:

client = risa.client_from_app(bot, hooks=[audit])
client.add_view(Poll)
On the pipeline Says whether
pipeline.failed Anything in the click has failed so far
pipeline.any_hook_failed A hook did
pipeline.invocation_failed load(), the handler or a fallback did

risa saves what the handler changed before POST_INVOKE begins, so a failing audit cannot cost a vote, and auto-defer still acknowledges the click.

A hook can change the view's state, which is rarely a good idea. ExecutionHook says when such a change is saved.

With or without the view¶

A hook whose third parameter is annotated with a view class gets the view, and runs only on clicks that have one. A hook without that parameter also runs on clicks that go to the view's fallbacks: on_outdated for a component the view can no longer route, and on_state_missing for a state that is gone. On such a click the fallback runs in place of INVOKE, without auto-defer.

Which hooks run on which click
The click Hooks without the view Hooks that take the view
Reaches the view The client's, the view's and the handler's The client's, the view's and the handler's
Its stored state is gone or no longer fits The client's, the view's and the handler's None
Its handler was retired, or its wire arguments no longer fit The client's and the view's None
Cannot reach its state None None

A click cannot reach its state when the store is down, the lock timed out, a codec's extra is missing or the client lacks the view's store. It goes straight to the error handlers with a STATE failure.

Annotate the view parameter with the class alone, and attach the hook where its view is. @risa.hook has both rules.

Parameters after these are injected, as a handler's are, and their types have to exist at runtime. That includes the pipeline: a factory, or a function the hook calls, can take risa.ExecutionPipeline. A handler can too, but there it is always empty, since the handler runs only when nothing has failed.

Steps of your own¶

Within one step, the client's hooks run before the view's. To audit after every other hook, give the audit a step of its own after POST_INVOKE:

LAST = risa.ExecutionStep("LAST")


@risa.hook(LAST)
async def audit_last(pipeline: risa.ExecutionPipeline, ctx: risa.ComponentContext) -> None:
    outcome = "failed" if pipeline.failed else "ran"
    AUDIT.info("%s clicked on message %s, which %s", ctx.user.id, ctx.message.id, outcome)


client = risa.client_from_app(
    bot,
    hooks=[audit_last],
    execution_step_order=[*risa.DEFAULT_EXECUTION_STEP_ORDER, LAST],
)

execution_step_order holds INVOKE once and every other step at most once, or the client raises ValueError. A hook in a step the order leaves out never runs, and risa logs a warning when the client is made or the view added.

Testing a hook¶

A hook is callable, so a test can await it with a pipeline of its own. ctx is whatever stands in for the context in your tests, such as a mock:

async def test_author_only_lets_the_author_through(ctx: risa.ComponentContext) -> None:
    poll = Poll(question="Pizza on Friday?", author_id=ctx.user.id)
    await author_only(risa.ExecutionPipeline(), ctx, poll)

risa.ExecutionPipeline([risa.Failure(error, risa.FailureStage.HANDLER)]) makes a pipeline that has failed, for an error handler or a hook after the handler.

Full file 
"""Hooks: a check only the poll's author passes, its answer, and an audit after every click."""

from __future__ import annotations

import logging
import os

import hikari

import risa
from risa import ui

AUDIT = logging.getLogger("bot.audit")


class NotTheAuthorError(Exception):
    """Someone other than the author tried to close the poll."""


@risa.hook(risa.ExecutionSteps.CHECKS)
async def author_only(_pipeline: risa.ExecutionPipeline, ctx: risa.ComponentContext, poll: Poll) -> None:
    if ctx.user.id != poll.author_id:
        raise NotTheAuthorError


@risa.register(name="closable-poll")
class Poll(risa.View):
    question: str
    author_id: int
    yes: int = 0
    no: int = 0
    closed: bool = False

    def render(self) -> ui.Layout:
        return ui.Container(
            ui.TextDisplay(f"## {self.question}" + (" (closed)" if self.closed else "")),
            ui.Row(
                ui.Button(self.vote_yes, label=f"Yes: {self.yes}", disabled=self.closed),
                ui.Button(self.vote_no, label=f"No: {self.no}", disabled=self.closed),
                ui.Button(self.close, label="Close", style=hikari.ButtonStyle.DANGER, disabled=self.closed),
            ),
        )

    @risa.handler
    async def vote_yes(self, ctx: risa.ComponentContext) -> None:
        if not self.closed:
            self.yes += 1
        await ctx.rerender()

    @risa.handler
    async def vote_no(self, ctx: risa.ComponentContext) -> None:
        if not self.closed:
            self.no += 1
        await ctx.rerender()

    @risa.handler(hooks=[author_only])
    async def close(self, ctx: risa.ComponentContext) -> None:
        self.closed = True
        await ctx.rerender()


def add_error_handlers(client: risa.Client) -> None:
    @client.error_handler
    async def not_the_author(pipeline: risa.ExecutionPipeline, ctx: risa.ComponentContext) -> bool:
        if pipeline.find(NotTheAuthorError) is None:
            return False
        await ctx.respond("Only the author can close this poll.", ephemeral=True)
        return True


@risa.hook(risa.ExecutionSteps.POST_INVOKE)
async def audit(pipeline: risa.ExecutionPipeline, ctx: risa.ComponentContext) -> None:
    outcome = "failed" if pipeline.failed else "ran"
    AUDIT.info("%s clicked on message %s, which %s", ctx.user.id, ctx.message.id, outcome)


def make_client(bot: hikari.GatewayBot) -> risa.GatewayEnabledClient:
    client = risa.client_from_app(bot, hooks=[audit])
    client.add_view(Poll)
    add_error_handlers(client)
    return client


LAST = risa.ExecutionStep("LAST")


@risa.hook(LAST)
async def audit_last(pipeline: risa.ExecutionPipeline, ctx: risa.ComponentContext) -> None:
    outcome = "failed" if pipeline.failed else "ran"
    AUDIT.info("%s clicked on message %s, which %s", ctx.user.id, ctx.message.id, outcome)



def make_client_that_audits_last(bot: hikari.GatewayBot) -> risa.GatewayEnabledClient:
    client = risa.client_from_app(
        bot,
        hooks=[audit_last],
        execution_step_order=[*risa.DEFAULT_EXECUTION_STEP_ORDER, LAST],
    )
    client.add_view(Poll)
    add_error_handlers(client)
    return client


async def test_author_only_lets_the_author_through(ctx: risa.ComponentContext) -> None:
    poll = Poll(question="Pizza on Friday?", author_id=ctx.user.id)
    await author_only(risa.ExecutionPipeline(), ctx, poll)


def main() -> None:
    bot = hikari.GatewayBot(
        os.environ["DISCORD_TOKEN"],
        intents=hikari.Intents.ALL_UNPRIVILEGED | hikari.Intents.MESSAGE_CONTENT,
    )
    client = make_client(bot)

    @bot.listen()
    async def on_message(event: hikari.GuildMessageCreateEvent) -> None:
        if event.content == "!poll":
            poll = Poll(question="Pizza on Friday?", author_id=event.author.id)
            rendered = await client.build(poll)
            await rendered.send_to(bot.rest, event.channel_id)

    bot.run()


if __name__ == "__main__":
    main()
