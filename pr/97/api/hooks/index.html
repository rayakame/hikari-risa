risa.hooks¶

Hooks, the steps they run in, and the pipeline every click runs through.

DEFAULT_EXECUTION_STEP_ORDER module-attribute ¶

DEFAULT_EXECUTION_STEP_ORDER: Final[Sequence[ExecutionStep]] = (
    ExecutionSteps.MAX_CONCURRENCY,
    ExecutionSteps.CHECKS,
    ExecutionSteps.COOLDOWNS,
    ExecutionSteps.PRE_INVOKE,
    ExecutionSteps.INVOKE,
    ExecutionSteps.POST_INVOKE,
)

The order a client runs the steps in unless it is given another.

ExecutionHook ¶

ExecutionHook(
    func: Callable[..., Awaitable[None]],
    *,
    step: ExecutionStep,
    skip_when_failed: bool,
    name: str,
)

A function risa runs in one step of every click it reaches, made by @risa.hook.

Attach it with hooks=[...] to the client, to @risa.register or to @risa.handler. Within a step, the client's hooks run first, then the view's, then the handler's.

A hook can change the view's state. Before the handler, the handler's save takes the change along, and the change is lost if the handler or a hook before it fails. After the handler, the hook has to call ctx.rerender() to save it, which works only while nothing in the click has failed. A change it leaves unsaved is lost, and if nothing in the click failed, risa logs a warning.

func: Callable[..., Awaitable[None]]

The decorated function.

name property ¶

name: str

The hook's name, the function's by default.

skip_when_failed property ¶

skip_when_failed: bool

Whether the hook is skipped once something in the click has failed.

step property ¶

step: ExecutionStep

The step the hook runs in.

ExecutionPipeline ¶

ExecutionPipeline(failures: Sequence[Failure] = ())

The run of one click, and what has failed in it so far.

Every click risa answers has one. Hooks and error handlers receive it first; a handler, View.on_outdated or View.on_state_missing can have it injected. Make one yourself to call a hook or an error handler in a test.

@client.error_handler
async def on_error(
    pipeline: risa.ExecutionPipeline, ctx: risa.ComponentContext
) -> bool:
    if pipeline.find(NotTheAuthorError) is None:
        return False
    await ctx.respond("You cannot interact with this.", ephemeral=True)
    return True

Parameters:

  • failures (Sequence[Failure], default: () ) –

    What has failed in the click so far, none by default.

invocation_failed: bool

ExecutionStep ¶

ExecutionStep(name: str)

Bases: Struct

A step of a click that hooks run in.

ExecutionSteps holds the built-in ones. Make your own with a name of your choice and put it into the client's execution_step_order.

Attributes:

  • name (str) –

    The step's name; two steps with one name are the same step.

ExecutionSteps ¶

The built-in execution steps, in the order a client runs them by default.

Attributes:

  • MAX_CONCURRENCY (Final[ExecutionStep]) –

    For hooks that limit how many clicks run at once.

  • CHECKS (Final[ExecutionStep]) –

    For hooks that decide whether the click may run at all.

  • COOLDOWNS (Final[ExecutionStep]) –

    For hooks that limit how often a click may run.

  • PRE_INVOKE (Final[ExecutionStep]) –

    For hooks that run right before the handler.

  • INVOKE (Final[ExecutionStep]) –

    The view's load and the handler, or View.on_outdated or View.on_state_missing for a click that cannot reach the view. No hook runs in it.

  • POST_INVOKE (Final[ExecutionStep]) –

    For hooks that run after the handler, even after a failure.

FailureStage ¶

Bases: StrEnum

Where a click failed, as Failure.stage names it.

Attributes:

  • HANDLER –

    The handler raised.

  • LOAD –

    The view's load raised, so the handler never ran.

  • HOOK –

    A hook raised; Failure.hook says which.

  • ON_OUTDATED –

  • ON_STATE_MISSING –

    View.on_state_missing raised.

hook ¶

hook(
    step: ExecutionStep,
    /,
    *,
    skip_when_failed: bool = False,
    name: str | None = None,
) -> _HookDecorator

Make a function a hook that runs in step.

@risa.hook(risa.ExecutionSteps.CHECKS)
async def author_only(
    pipeline: risa.ExecutionPipeline, ctx: risa.ComponentContext, view: Poll
) -> None:
    if ctx.user.id != view.author_id:
        raise NotTheAuthorError(ctx.user.id)

A hook takes the pipeline and a ComponentContext. A third parameter annotated with a view class gets the view, with its durable state, and the hook then runs only on clicks that reach one; without it the hook runs on every click that reaches the view or one of its fallbacks, View.on_outdated and View.on_state_missing. Every further parameter is injected, as a handler's are. A hook fails the click by raising: a handler that has not run yet no longer runs, the exception reaches the error handlers, and the hooks after it still run unless they were made with skip_when_failed=True.

Annotate the view parameter with the class alone: for Poll | None, client.add_view raises HookDeclarationError. A hook for one view class belongs on that view or its handlers, or its view parameter names a base class of every view it runs for. Your type checker refuses a Poll hook on the client, and client.add_view raises HookDeclarationError for a hook that takes a view of another class. With use_global=True, a view never passes through add_view, so there the hook fails each click that reaches it with that error.

Parameters:

  • step (ExecutionStep) –

    The step the hook runs in.

  • skip_when_failed (bool, default: False ) –

    Skip the hook once something in the click has failed.

  • name (str | None, default: None ) –

    The hook's name in logs, the function's by default.

Returns:

  • _HookDecorator –

    The decorator that makes the hook.

Raises:

  • HookDeclarationError –

    If step is ExecutionSteps.INVOKE, which runs the handler and no hooks.
